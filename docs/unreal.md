# The Unreal plugin

`unreal/Hanji` is an Unreal Engine 5.8 plugin. It compiles the core from `core/` into its module, so clone the whole repository into a project's `Plugins` folder (Unreal finds `unreal/Hanji/Hanji.uplugin` there), or point the project at it with `AdditionalPluginDirectories`, as `unreal/HanjiSample` does.

## Pieces

| Piece | What it does |
|---|---|
| `UHanjiClipTable` | A data asset holding the atlas texture and its JSON: a pose-atlas contract, Aseprite JSON or `hanji-clips`, plus optional overlay (contact frames, events, hitboxes) and policies. The JSON is stored in the asset, so packaged games need no loose files; *Reload From Files* reads it again in the editor. Errors and warnings are shown on the asset. |
| `UHanjiSpriteComponent` | One character. Frame from the Hanji clock; heading from `SetFacingDirection` with hysteresis and policy-driven facing locks; the quad standing at `TiltDegrees` with its ground pivot on `AnchorOffset` (edit that, not the component's location); optional pixel snapping; `OnFrameEvent` and `OnActionFinished`; `HitStop` and `ApplyStateHitStop`, mirrored to the owner's `CustomTimeDilation`; `GetActiveBoxes` in world space; `AttachToPixel` for effects; a blob-shadow decal. It never ticks. |
| `UHanjiSubsystem` | Advances every sprite once per frame with the player camera's rotation (or one set with `SetViewRotation`). |
| `AHanjiCamera` | A fixed-angle orthographic follow camera with eased zoom steps (90, 100 and 110 % by default) that snaps its rendered position to the screen-pixel lattice of the current zoom. |
| Materials | `M_HanjiSprite` (lit) and `M_HanjiSpriteUnlit`: masked, two-sided, *Has Pixel Animation* on, parameters `Atlas`, `FrameUV` and `Mirror`. `M_HanjiBlobShadow`: a deferred decal. Generated by `Scripts/make_assets.py`. |

## Building and testing

GitHub's runners have no Unreal, so the plugin is built and tested locally:

```powershell
unreal\hanji-unreal.ps1 -Mode All      # build HanjiSampleEditor, run the Hanji.* automation tests headless
unreal\hanji-unreal.ps1 -Mode Assets   # regenerate the mesh and materials (committed)
```

The test run fails unless it produces a fresh report; process exit alone is not counted as success. Eight automation tests cover the clip-table asset, the shipped assets, pivot placement at three tilts, frames, events, the facing lock, hitboxes, hit-stop on the sprite and its owner, the blob shadow, pixel attachments, depth tie-breaking, the camera's zoom and snapping, and the subsystem.

## Measurements

Measured on 4 November 2026 in a vertical slice: a private candidate of the author's game with its character's atlas (976 cells of 256 px in eight headings: idle, a 48-frame distance-driven walk, a 25-frame jab, eight stop variants), on one PC. The character's art is not part of this repository; the numbers are.

| What | Result |
|---|---|
| Contact frame and hit event at 0.5×, 1× and 2× attack speed (5/4/15 frames at 60 Hz at 1×) | The hit fires on the first active 60 Hz tick (10, 5 and 3), and the contact frame is drawn on that tick at all three speeds. At 2× it is drawn because the crossing tick holds it; without that it was skipped. |
| Heading flicker, stick held on a sector boundary with ±2° noise for 600 ticks | 324 flips without hysteresis, 0 with 3°. |
| Stride | One cycle of distance (336.5 cm) shows all 48 walk frames once; standing still holds the frame. Foot slide also depends on the cycle calibration, which the character's contract marks provisional. |
| Hit-stop | A jab with a stop at its contact fires one hit and one whoosh event. |
| Update cost on the game thread (walking sprites, facing and travel changing every frame) | 2.2 µs per sprite: 0.002 ms for 1, 0.10 ms for 50, 0.42 ms for 200. |
| TSR against no anti-aliasing, eight captures during walking, turning, the jab and both zoom steps | At most 0.065 % of pixels differ by more than 48 of 255; no trails behind moving sprites in the captures. A visual check, not a perceptual study. |

Two defects were found by the slice and fixed: the sprite material failed to compile for SM6 (a three-channel output masked for four), and two sprites on one depth line rendered the one behind black (now broken by a per-sprite depth offset).

Not yet measured: lit sprites in a lit scene (the slice uses the unlit material; the lit one needs a lighting setup, roadmap item 11), occluder fade and silhouette (Stage 2), and a packaged build.
